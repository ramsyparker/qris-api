# Error handling

The SDK throws `QrisApiError` when the server returns a failed HTTP status. It contains the response `status`, `message`, and `body`. Input rejected by the SDK causes a `TypeError`; network failures surface as errors from `fetch`.

```ts
import { QrisApiError } from '@aaramsyy/qris-api';

try {
  await api.convert({ qris: '<VALID_QRIS>', nominal: '10000' });
} catch (error) {
  if (error instanceof QrisApiError) {
    console.error('Status:', error.status);
    console.error('Message:', error.message);
    console.error('Response:', error.body);
  } else {
    console.error('No API response was received.', error);
  }
}
```

## Common statuses

| Status | What to do |
| --- | --- |
| `400` | Check input format, the QRIS payload, or image clarity. |
| `429` | Reduce request frequency before retrying. |
| `500` | Retry; if the error persists, check server logs. |

The SDK checks basic types and formats before sending a request. The server validates QRIS content and CRC.
